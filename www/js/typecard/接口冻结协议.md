# typecard V2 · 接口冻结协议（2026-10-08）

> 本文档为接口冻结版，是后续 engine / ui / controller 实现的唯一契约依据。
> 核心铁律：generator 只拆解已有回复文本，输入什么、最终拼出的 text 就一字不差还原什么。
> 选错/删除/选标点是打字过程中「随机真实发生的事件」，不是预先安排的演出。

## 1. generator.js 输入输出协议

### 输入（Input）
```
buildSession(text, opts)
  text : string          // 完整回复文本（来自主线 deliverReply 已生成内容），只读，绝不改写
  opts : {
    mistakeRate? : number   // 单次选错概率，默认 0.18（0~1）
    speedRange?  : [minMs, maxMs]  // 打字速度区间，供 engine 使用（generator 不消费，仅透传）
    rng?         : () => number    // 可注入随机源（测试用），默认 Math.random
  }
```

### 输出（Output）
返回一个 **session 对象**（逐步生成器），不预生成全部步骤：

```
session = {
  source: text,              // 原文（只读，用于最终校验）
  next(): Step | null,       // 驱动产生「下一个随机发生的打字事件」，返回 null 表示已拼完
  text: string,              // 当前已拼出的文本（随 next() 推进）
  done: boolean              // 是否拼完（text === source 时 true）
}
```

### 不变量（Invariant，必须保证）
1. `session.text` 永远是 `session.source` 的一个**前缀**（逐字），绝不出现原文以外的字。
2. `next()` 推进结束后，`session.text` 最终**严格等于** `session.source`（一字不差）。
3. 选错/删除/选标点都是 next() 过程中**随机真实发生**的事件，但只影响"过程"，最终 text 还原原文。

## 2. step 数据结构（next() 返回的事件）

```js
// 一个 Step 描述一次「真实发生的打字动作」，type 区分动作种类：
{
  type: 'letter' | 'candidate' | 'pick' | 'mistake' | 'delete' | 'punct' | 'done',
  // 各 type 携带字段：
  // letter     : { ch, pinyin, letter, letterIndex }   // 拼音逐字母敲出
  // candidate  : { ch, pinyin, candidates[], target } // 候选字弹出（target=正确字）
  // pick       : { ch }                                 // 选中一个字上屏（text 追加 ch）
  // mistake    : { ch, wrong }                          // 选错：本想选 ch，错选了 wrong
  // delete     : { removed }                            // 删除刚上屏的错字
  // punct      : { ch }                                 // 从操作行选标点上屏
  // done       : { text }                               // 拼完，text 应为原文
}
```

关键：`pick`/`punct` 上屏的字**必须等于原文对应位置的字**；`mistake`+`delete` 是过程中的真实随机事件，删除后重新 pick 正确字。

## 3. engine 消费接口（冻结）

```js
// engine 通过 session 逐步驱动演出
const session = bmTypecardGenerator.buildSession(replyMsg.content, opts);

while (!session.done) {
  const step = session.next();
  if (!step) break;
  await bmTypecardUi.play(step, session);  // ui 渲染这一步，返回 Promise（随机时长）
}
// 演完：session.text === replyMsg.content，engine 调 finish 落库原消息
```

engine 职责：生命周期（idle/playing/finishing/aborting）、按 speedRange 控制节奏、abort 时立即上屏完整真消息。

## 4. ui 消费接口（冻结）

```js
bmTypecardUi.play(step, session) -> Promise<void>
// 根据 step.type 渲染对应动作：
//   letter    -> 拼音行追加一个字母 + 光标后移
//   candidate -> 候选行弹出候选字（光标在字间移动）
//   pick      -> 候选高亮该字，确定上屏到正文预览
//   mistake   -> 高亮错字（闪烁红/淡紫提示）
//   delete    -> 删除键高亮，正文预览删掉最后那个错字
//   punct     -> 操作行标点高亮，标点上屏
//   done      -> 收尾淡出
```

ui 职责：输入法面板三行显示、正文预览区（主体、完整不裁切）、动作反馈高亮、气泡内嵌/悬浮窗容器。不决策、不计算步骤。

## 5. 明确禁止（本轮 + 后续）

- ❌ 随机生成回复内容
- ❌ 修改回复内容（text 必须逐字还原原文）
- ❌ 修改 app.js（本轮）
- ❌ 修改数据库（本轮）
- ❌ 把选错/删除/标点做成"预编排演出"——它们是 next() 中随机真实发生的事件
